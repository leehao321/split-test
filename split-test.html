测试原理与注意事项
  • 怎么测的：浏览器里的网页发不了 CONNECT，也拿不到单独的 TCP 握手时间，只能发 HTTPS 请求。「复用连接」模式（默认）先请求一次 https://域名/favicon.ico 把连接建好（不计入结果），再在这条连接上发几次 HEAD 请求取最小值，得到的是一次往返加服务器处理的时间，比首次请求更接近代理软件里的延迟数字。前提是连接真的被复用了：经过代理时，浏览器或代理软件可能给每个请求新开一条隧道，这时数字里仍然含建连时间，会偏大，不能据此断定节点慢。「首次请求」模式是老的测法，结果包含 DNS、TCP、TLS 建连时间。
  • GFW 自选列表：填你关心的域名，页面按同样的方式测能否连上。结果只能说明「从当前浏览器能不能访问」：不可达可能是被墙，也可能是站点故障或被内容拦截器拦了。开着代理测，看的是代理规则有没有覆盖到；关掉代理测，看的才是直连是否被墙。
  • 怎么判断分流：浏览器看不到每个请求具体走了哪条线路，所以主要看上方出口 IP：国内源和海外源查到的 IP 不同，说明分流生效；再结合两组站点的可达率和延迟判断规则有没有漏。
  • 「失败」表示很快就报错（连接被重置、DNS 解析失败、被广告拦截插件拦截等）；「超时」表示在设定时间内没有任何响应。
  • 建议直接用电脑浏览器打开本文件测试。如果浏览器开了「安全 DNS」，或者浏览器的代理设置和代理软件不一致，结果可能和其它应用不同。
  • 历史对比：每个站点最近两次的结果存在本机浏览器里，刷新后还在。卡片右下角的 ↑/↓ 是和上一次相比延迟变化的毫秒数（相差不到 20ms 显示 ≈），出口 IP 变了会在提示里说明。点「清除记录」可以清空。
  • 点击任意卡片可以单独重测该站点。站点列表在源码的 DATA 里，可以自行增删。
