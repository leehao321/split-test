测试原理与注意事项
  • 怎么测的：浏览器里的网页发不了 CONNECT，也拿不到单独的 TCP 握手时间，只能发 HTTPS 请求。「复用连接」模式（默认）先请求一次 https://域名/favicon.ico 把连接建好（不计入结果），再在这条连接上发几次 HEAD 请求取最小值，得到的是一次往返加服务器处理的时间，比首次请求更接近代理软件里的延迟数字。前提是连接真的被复用了：经过代理时，浏览器或代理软件可能给每个请求新开一条隧道，这时数字里仍然含建连时间，会偏大，不能据此断定节点慢。「首次请求」模式只取第一次请求的耗时，包含 DNS、TCP、TLS 建连时间，这个模式下「轮次」不起作用。注意：刚测过的站点，浏览器可能还留着那条连接，马上重测时第一次请求也可能不含建连。
  • GFW 自选列表：填你关心的域名，页面按同样的方式测能否连上。结果只能说明「从当前浏览器能不能访问」：不可达可能是被墙，也可能是站点故障或被内容拦截器拦了。开着代理测，看的是代理规则有没有覆盖到；关掉代理测，看的才是直连是否被墙。
  • 怎么判断分流：浏览器看不到每个请求具体走了哪条线路，所以主要看上方出口 IP：国内源和海外源查到的 IP 不同，说明分流生效；再结合两组站点的可达率和延迟判断规则有没有漏。
  • 「失败」表示很快就报错（连接被重置、DNS 解析失败、被广告拦截插件拦截等）；「超时」表示在设定时间内没有任何响应。
  • 建议直接用电脑浏览器打开本文件测试。如果浏览器开了「安全 DNS」，或者浏览器的代理设置和代理软件不一致，结果可能和其它应用不同。
  • 历史对比：每个站点最近两次的结果存在本机浏览器里，刷新后还在。卡片右下角的 ↑/↓ 是和上一次相比延迟变化的毫秒数（相差不到 20ms 显示 ≈）。每次批量测试开始前会自动刷新出口 IP；出口换了会在提示里说明，按网段比较，同一出口在同网段里轮换 IP 不算。点「清除记录」可以清空。
  • IPv6 泄露：用只有 IPv6 地址的查询源查一次出口，再和海外 IPv4 出口的归属（国家、ASN）比。没有 IPv6 出口说明 IPv6 流量出不去，自然不会泄露；IPv6 出口在国内而海外 IPv4 出口在国外，就是 IPv6 绕过了代理。
  • WebRTC 泄露：页面像视频通话网站一样向 STUN 服务器要一次自己的公网地址。拿到的地址如果不是海外出口，任何海外网站都能用同样的办法看到它。电脑上用「系统代理」模式时最常见；TUN 模式或者 iPhone 上的代理 App 一般不会泄露。
  • 线路推测：浏览器看不到每个请求走哪条线路，所以用延迟推测：国内组和美国组的中位延迟分别代表两条线路的典型值，某个国内站点的延迟明显像海外线路、或者某个海外站点明显像国内线路，就标成「线路可疑」（卡片名称前有琥珀色圆点）。两组延迟太接近（相差不到一倍）时不做推测。有些海外网站在国内有节点（Apple、微软等），直连时也会被标出来，这是正常的。
  • 生成规则：把不可达和线路可疑的站点生成分流规则，支持 Clash（Mihomo / Stash）、Surge、小火箭、Quantumult X、Loon。国内站点用「国内站点策略」，美国组和 GFW 列表用「海外站点策略」。默认按主域名生成（比如 mail.google.com → google.com），覆盖面更大，用前请检查。
  • 节点对比和稳定性：每轮批量测试会自动保存一条记录（最多 60 轮，逐站点结果保留最近 12 轮），在「节点对比」里看趋势图、勾两轮比较差别。测之前在「本轮名称」里填节点名，比较时更好认。「复用连接」模式下每个站点会测几次，抖动是最慢减最快，复测失败是这几次里没连上的次数。定时复测需要页面一直开着；手机锁屏或切到别的 App 时会暂停，回来后补测。
  • 编辑列表：三组站点都可以在「编辑列表」里改，每行一个站点。「导出全部」得到一个 JSON 文件，换浏览器或换手机时用「导入文件」恢复。
  • 添加到主屏幕（iPhone）：在 Safari 里点分享 → 添加到主屏幕。从主屏幕打开没有地址栏，像一个 App；它的测试记录和 Safari 里的是分开保存的。
  • 点击任意卡片可以查看详情（各次延迟、抖动、首次请求耗时、线路推测、上一次的结果和当时的出口 IP）并单独重测。
